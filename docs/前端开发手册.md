# 前端开发手册

本文档面向 `light-shadow-wallpaper-client-admin` 的前端二次开发，结合本项目实际代码组织，并参考 Ballcat 前端文档：

- ProTable：https://www.ballcat.cn/guide/front/pro-table.html
- 字典：https://www.ballcat.cn/guide/front/dict.html
- Lov Local：https://www.ballcat.cn/guide/front/lov-local.html
- 前端部署：https://www.ballcat.cn/guide/front/front-deploy.html
- 动态路由：https://www.ballcat.cn/guide/front/react-antd-pro-v5-dynamic-route.html

## 1. 技术栈

项目基于 Ballcat Vue3 前端模板二次开发，核心技术如下：

- Vue 3.3 + `<script setup lang="ts">`
- Vite 4
- TypeScript 5
- Pinia
- Vue Router 4
- Ant Design Vue 3
- `pro-components` 本地移植版：ProLayout、ProTable、ProCard 等
- Axios 请求封装
- Vue I18n
- pnpm 包管理

项目强制使用 pnpm。不要使用 npm 或 yarn 安装依赖。

```bash
pnpm install
pnpm run dev
pnpm run build
pnpm run lint
```

本地开发默认由 Vite 代理 `/api` 到 `vite.config.ts` 中的 `serverAddress`，当前为：

```ts
const serverAddress = 'http://127.0.0.1:9527'
```

环境变量文件：

- `.env.development`：开发环境，`VITE_API_TIME_OUT=30000`
- `.env.production`：生产环境，`VITE_API_TIME_OUT=10000`
- `.env.test`：测试环境

常用变量：

```env
VITE_API_URL=/api
VITE_API_TIME_OUT=30000
VITE_PASSWORD_SECRET_KEY===BallCat-Auth==
VITE_IMAGE_DOMAIN=https://oss.breadj.com
```

## 2. 目录规范

核心目录说明：

```text
src
├─ api                 接口定义和接口类型
├─ assets              静态资源
├─ components          业务通用组件
├─ config              项目配置
├─ hooks               组合式业务 hooks
├─ layouts             布局组件
├─ locales             国际化
├─ router              静态路由、动态路由、路由守卫
├─ stores              Pinia 状态
├─ styles              全局样式
├─ utils               工具函数和 axios 封装
└─ views               页面

pro-components        Ballcat Pro 组件移植代码
types                 自动生成类型声明
```

二次开发原则：

- 业务代码放在 `src` 下。
- `pro-components` 是模板组件库移植代码，README 已说明二开时不要直接修改内部文件；需要扩展时优先在 `src/components` 或页面层封装。
- 新业务模块按照 `src/api/<业务域>/<模块>` 与 `src/views/<业务域>/<模块>` 成对组织。
- 页面组件建议以 `XxxPage.vue`、`XxxPageSearch.vue`、`XxxFormModal.vue` 命名。

## 3. 全局配置

项目配置集中在 `src/config/index.ts`：

- `projectTitle`：浏览器标题和布局标题
- `projectDesc`：项目描述
- `storageKeyPrefix`：本地存储 key 前缀
- `enableWebsocket`：是否启用 websocket
- `enableLayoutSetting`：是否启用布局设置
- `enableLoginCaptcha`：是否启用登录验证码
- `enableI18n`：是否启用国际化
- `defaultLanguage`、`supportLanguage`：语言配置
- `loginPath`：登录页路径
- `appSettings`：ProLayout 默认设置

新增全局开关时优先放在此文件，避免散落在页面中。

## 4. 请求与接口

### 4.1 返回结构

统一返回类型在 `src/api/types.ts`：

```ts
export interface ApiResult<T = unknown> {
  code: number
  data: T
  message: string
}

export interface PageParam {
  current?: number
  size?: number
  sort?: string
  [key: string]: any
}

export interface PageResult<T> {
  records: T[]
  total: number
}
```

分页接口的业务参数一般定义为：

```ts
export interface XxxQO {
  name?: string
  status?: number
}

export type XxxPageParam = XxxQO & PageParam
```

### 4.2 Axios 封装

请求入口为 `src/utils/axios/index.ts`，核心行为：

- 自动从 `user-store` 读取 `accessToken`，注入 `Authorization: Bearer <token>`。
- 自动注入 `Accept-Language`。
- JSON 响应返回 `response.data`。
- 400、401、403 和其他异常统一弹窗或通知。
- 401 时清理登录状态并跳转登录页。

底层 `HttpClient` 在 `src/utils/axios/http-client.ts`：

- 使用 `qs.stringify` 序列化 query 参数。
- 空字符串不会提交到后端。
- 数组按 repeat 格式提交，例如 `a=1&a=2`。
- 使用 `json-bigint` 解析响应，避免大整数精度丢失。

业务接口示例：

```ts
import httpClient from '@/utils/axios'
import type { ApiResult } from '@/api/types'
import type { WallpaperDTO, WallpaperPageParam, WallpaperPageVO } from './types'

export function pageWallpaper(pageParams: WallpaperPageParam) {
  return httpClient.get<ApiResult<WallpaperPageVO>>('/wallpaper/wallpaper/page', {
    params: pageParams
  })
}

export function createWallpaper(dto: WallpaperDTO) {
  return httpClient.post<ApiResult<void>>('/wallpaper/wallpaper', dto)
}

export function updateWallpaper(dto: WallpaperDTO) {
  return httpClient.put<ApiResult<void>>('/wallpaper/wallpaper', dto)
}

export function deleteWallpaper(id: number) {
  return httpClient.delete<ApiResult<void>>(`/wallpaper/wallpaper/${id}`)
}
```

### 4.3 操作型请求

删除、复制、启停等操作使用 `doRequest`：

```ts
import { doRequest } from '@/utils/axios/request'

doRequest(deleteWallpaper(record.id), {
  successMessage: '删除成功！',
  onSuccess: () => reloadTable()
})
```

`doRequest` 会按 `ApiResult.code` 判断成功，并统一处理成功、失败、异常提示。

## 5. CRUD 页面开发规范

一个标准列表页面通常由四类文件组成：

```text
src/api/<domain>/<module>/index.ts
src/api/<domain>/<module>/types.ts
src/views/<domain>/<module>/XxxPage.vue
src/views/<domain>/<module>/XxxPageSearch.vue
src/views/<domain>/<module>/XxxFormModal.vue
```

### 5.1 页面主组件

主页面负责：

- 渲染查询表单
- 渲染 ProTable
- 定义 columns
- 维护查询参数
- 打开新增、编辑弹窗
- 执行删除等操作

推荐结构：

```vue
<template>
  <xxx-page-search :loading="tableRef?.loading" @search="searchTable" />

  <pro-table
    ref="tableRef"
    header-title="模块管理"
    row-key="id"
    :request="tableRequest"
    :columns="columns"
    :scroll="{ x: 1000 }"
  >
    <template #toolBarRender>
      <new-button v-if="hasPermission('xxx:xxx:add')" @click="handleNew" />
    </template>

    <template #bodyCell="{ column, record }">
      <template v-if="column.key === 'operate'">
        <operation-group>
          <a v-if="hasPermission('xxx:xxx:edit')" @click="handleEdit(record)">编辑</a>
          <delete-text-button
            v-if="hasPermission('xxx:xxx:del')"
            @confirm="() => handleDelete(record)"
          />
        </operation-group>
      </template>
    </template>
  </pro-table>

  <xxx-form-modal ref="formModalRef" @submit-success="reloadTable" />
</template>
```

关键逻辑：

```ts
import ProTable from '#/table'
import type { ProColumns, ProTableInstanceExpose, TableRequest } from '#/table'
import { mergePageParam } from '@/utils/page-utils'
import { useAuthorize } from '@/hooks/permission'

const { hasPermission } = useAuthorize()
const tableRef = ref<ProTableInstanceExpose>()
const formModalRef = ref<InstanceType<typeof XxxFormModal>>()

let searchParams: XxxQO = {}

const reloadTable = (resetPageIndex?: boolean) => {
  tableRef.value?.actionRef?.reload(resetPageIndex)
}

const tableRequest: TableRequest = (params, sorter, filter) => {
  const pageParam = mergePageParam(params, sorter, filter)
  return pageXxx({ ...pageParam, ...searchParams })
}

const searchTable = (params: XxxQO) => {
  searchParams = params
  reloadTable(true)
}
```

### 5.2 查询组件

查询组件只负责表单状态和发出 `search` 事件，不直接请求接口。

```ts
const emits = defineEmits<{
  (e: 'search', params: Record<string, any>): void
}>()

const formModel = reactive<XxxQO>({
  name: '',
  status: undefined
})

const search = () => {
  emits('search', toRaw(formModel))
}

const reset = () => {
  resetFields()
  search()
}
```

项目中查询区目前使用 `a-card + a-form + a-row + a-col`，并通过 `SearchActions` 统一搜索、重置按钮。

### 5.3 表单弹窗

表单弹窗一般使用：

- `useModal` 控制标题和可见性。
- `useFormAction` 区分新增和编辑。
- `useAdminForm` 绑定表单校验和提交请求。
- `FormRequestMapping` 将 `CREATE`、`UPDATE` 映射到接口函数。
- `defineExpose({ open })` 暴露给父组件。

```ts
const { title, visible, openModal, closeModal } = useModal()
const { formAction, isUpdateForm } = useFormAction()

const formRequestMapping: FormRequestMapping<XxxDTO> = {
  [FormAction.CREATE]: createXxx,
  [FormAction.UPDATE]: updateXxx
}

const { submitLoading, validateAndSubmit, resetFields } = useAdminForm(
  formAction,
  formRequestMapping,
  formModel,
  formRule
)

const handleSubmit = () => {
  validateAndSubmit({ ...formModel }, {
    onSuccess: () => {
      closeModal()
      emits('submit-success')
    }
  })
}

defineExpose({
  open(newFormAction: FormAction, record?: XxxPageVO) {
    openModal()
    resetFields()
    title.value = newFormAction === FormAction.CREATE ? '新建' : '编辑'
    if (newFormAction === FormAction.UPDATE) {
      overrideProperties(formModel, record)
    }
    formAction.value = newFormAction
  }
})
```

## 6. ProTable 使用规范

Ballcat ProTable 参考 Ant Design ProTable 思路，封装了表格请求、工具栏、列配置、密度、刷新、全屏等能力。本项目 ProTable 位于 `pro-components/table`，通过别名 `#/table` 引入。

### 6.1 基础用法

```vue
<pro-table
  ref="tableRef"
  header-title="壁纸管理"
  row-key="id"
  :request="tableRequest"
  :columns="columns"
  :scroll="{ x: 1000 }"
/>
```

常用属性：

- `header-title`：表格标题。
- `row-key`：行唯一 key，通常为 `id`。
- `request`：远程请求函数。
- `columns`：列配置。
- `scroll`：横向滚动，列较多时必须配置。

### 6.2 request 写法

`request` 不直接拼接查询参数，统一使用 `mergePageParam` 处理分页、排序、过滤：

```ts
const tableRequest: TableRequest = (params, sorter, filter) => {
  const pageParam = mergePageParam(params, sorter, filter)
  return pageWallpaper({ ...pageParam, ...searchParams })
}
```

### 6.3 columns 写法

```ts
const columns: ProColumns[] = [
  {
    title: '序号',
    dataIndex: 'id',
    width: 80,
    align: 'center',
    fixed: 'left',
    customRender: ({ index }) => index + 1
  },
  {
    title: '状态',
    dataIndex: 'status',
    customRender: ({ value }) => h(DictText, { dictCode: 'wallpaper_status', value })
  },
  {
    title: '创建时间',
    dataIndex: 'createTime',
    width: 150,
    sorter: true
  },
  {
    key: 'operate',
    title: '操作',
    align: 'center',
    width: 160
  }
]
```

约定：

- 固定操作列时要设置 `width`。
- 字典值展示优先使用 `DictText`、`DictTag` 等组件。
- 时间格式化使用 `dayjs`。
- 长文本设置 `ellipsis: true`。
- 多列页面设置 `:scroll="{ x: ... }"`。

### 6.4 插槽

工具栏：

```vue
<template #toolBarRender>
  <new-button v-if="hasPermission('xxx:xxx:add')" @click="handleNew" />
</template>
```

单元格：

```vue
<template #bodyCell="{ column, record }">
  <template v-if="column.key === 'operate'">
    <operation-group>
      <a @click="handleEdit(record)">编辑</a>
    </operation-group>
  </template>
</template>
```

### 6.5 刷新表格

```ts
tableRef.value?.actionRef?.reload()
tableRef.value?.actionRef?.reload(true)
```

- `reload()`：保留当前页刷新。
- `reload(true)`：重置到第一页刷新，适合查询条件变化。

## 7. 字典

字典能力由 `src/components/Dict` 与 `src/stores/dict-store.ts` 提供，参考 Ballcat 字典文档实现。

### 7.1 缓存机制

`dict-store` 的行为：

- 先读内存缓存 `dictDataCache`。
- 再读 LocalStorage：`breadj-admin/dict:<dictCode>`。
- 缓存不存在时调用后端 `getDictData([dictCode])`。
- 使用 `dictRequestLocks` 避免同一字典重复请求。
- 使用 `dictHash` 和 `invalidDictHash` 校验缓存是否过期。
- 页面刷新后会执行一次 `checkDictData()`。

### 7.2 组件

常用组件：

- `DictSelect`：下拉选择。
- `DictRadioGroup`：单选组。
- `DictCheckboxGroup`：复选组。
- `DictText`：文本展示。
- `DictTag`、`DictTagGroup`、`DictBadge`：状态展示。

表单中使用：

```vue
<dict-select v-model:value="formModel.status" dict-code="wallpaper_status" />
```

表格中使用：

```ts
customRender: ({ value }) => h(DictText, { dictCode: 'wallpaper_status', value })
```

### 7.3 值类型

后端返回的字典值是字符串，`useDict` 会按字典的 `valueType` 转换为真实类型：

- number
- string
- boolean

因此业务字段类型要和字典配置保持一致。比如 `wallpaper_status` 如果是数字字典，表单字段就应为 `number | undefined`，不要写成字符串。

### 7.4 过滤和禁用

字典组件支持：

- `itemFilter`：过滤不需要展示的字典项。
- `itemDisabledChecker`：自定义禁用逻辑。

默认禁用逻辑为字典项状态不是启用时禁用。

## 8. Lov Local

Lov Local 用于“弹窗分页选择数据”，适合用户、角色、组织等数据量较大的选择场景。实现位于 `src/components/Lov`。

### 8.1 配置位置

统一配置建议放在：

```text
src/components/Lov/lov-options.ts
```

现有用户 Lov：

```ts
export const sysUserLov: LovProps<SysUserPageParam, SysUserPageVO> = {
  multiple: true,
  isNumberValue: true,
  modalTitle: '用户',
  dataKey: 'userId',
  customOptionTitle(record) {
    return record.nickname
  },
  getPageData: getUserPage,
  searchOptions: [
    {
      label: '用户名',
      field: 'username',
      type: LOV_SEARCH_TYPE_ENUM.INPUT,
      placeholder: enableI18n ? 'message.pleaseEnter' : '请输入'
    }
  ],
  tableColumns: [
    {
      title: '用户名',
      dataIndex: 'username'
    }
  ]
}
```

### 8.2 页面使用

```vue
<lov v-model="formModel.userIds" v-bind="sysUserLov" />
```

如果字段是数字类型，配置 `isNumberValue: true`，组件会在展示和提交间转换类型。

### 8.3 配置说明

- `multiple`：是否多选。
- `isNumberValue`：值是否为数字。
- `modalTitle`：弹窗标题。
- `dataKey`：唯一值字段。
- `customOptionTitle`：选择框内显示文本。
- `getPageData`：分页接口函数。
- `searchOptions`：弹窗查询条件。
- `tableColumns`：弹窗表格列。
- `tableSize`：表格尺寸。

### 8.4 注意事项

- `dataKey` 必须稳定且唯一。
- `customOptionTitle` 应返回用户能识别的名称，不要只展示 ID。
- 多选字段建议后端使用数组接收。
- Lov 的搜索和表格列只放选择需要的信息，避免弹窗过重。

## 9. 路由与菜单

项目使用服务端菜单生成动态路由，核心文件：

- `src/router/index.ts`
- `src/router/constant-routes.ts`
- `src/router/dynamic-routes.ts`
- `src/router/guards.ts`
- `src/stores/user-store.ts`

### 9.1 静态路由

静态路由包括：

- `/login`
- `/oauth2/authorize`
- `/oauth2/consent`
- 全局 404

定义在 `constant-routes.ts`，适合登录页、授权页、错误页等不依赖菜单的页面。

### 9.2 动态路由流程

登录后访问业务页面时，路由守卫会：

1. 判断是否存在 `accessToken`。
2. 如果未加载 `userMenus`，调用 `userStore.fetchUserMenus()`。
3. 使用 `generatorDynamicRouter(userMenus)` 生成路由。
4. 通过 `router.addRoute(dynamicRouter)` 动态挂载。
5. 返回 `to.fullPath` 重新进入目标路由。

### 9.3 菜单到路由的映射

后端菜单字段由 `SysMenuRouterVO` 表示。主要规则在 `dynamic-routes.ts`：

- 根路由固定使用 `BasicLayout.vue`。
- 菜单类型 `type = 0` 表示目录，组件使用 `RouterLayout.vue`。
- 菜单类型 `type = 1` 表示菜单页。
- `targetType = 1` 表示内置组件，通过 `item.uri` 匹配 `src/views`。
- `targetType = 2` 表示 iframe，组件使用 `src/views/basic/iframe/index.vue`。
- `targetType = 3` 表示外链。
- `hidden = 1` 时写入 `meta.hideInMenu = true`。

组件路径匹配顺序：

```text
/src/views/<componentPath>.vue
/src/views/<componentPath>/index.vue
/src/views/<componentPath>.tsx
/src/views/<componentPath>/index.tsx
```

如果匹配不到，开发环境会打印警告，并使用异常页组件。

### 9.4 新增页面路由

新增业务页面时：

1. 在 `src/views` 下创建页面文件。
2. 后端菜单 `uri` 配置为相对 `src/views` 的路径，例如：

```text
wallpaper/wallpaper/WallpaperPage
```

3. 配置菜单权限和按钮权限。
4. 重新登录或刷新页面，让前端重新拉取菜单。

## 10. 权限

页面按钮权限通过 `useAuthorize`：

```ts
const { hasPermission } = useAuthorize()
```

模板中使用：

```vue
<new-button v-if="hasPermission('wallpaper:wallpaper:add')" @click="handleNew" />
<a v-if="hasPermission('wallpaper:wallpaper:edit')" @click="handleEdit(record)">编辑</a>
<delete-text-button
  v-if="hasPermission('wallpaper:wallpaper:del')"
  @confirm="() => handleDelete(record)"
/>
```

权限码建议遵循：

```text
业务域:模块:操作
```

示例：

```text
wallpaper:wallpaper:add
wallpaper:wallpaper:edit
wallpaper:wallpaper:del
wallpaper:wallpaper:copy
```

前端权限只控制展示和交互，后端仍必须做权限校验。

## 11. 状态管理

Pinia store 位于 `src/stores`：

- `user-store.ts`：登录 token、用户信息、菜单。
- `dict-store.ts`：字典缓存。
- `i18n-store.ts`：语言状态。
- `multitab-store.ts`：多标签页。
- `setting-store.ts`：布局设置。

本地存储统一使用 `getStorageKey` 添加 `storageKeyPrefix`，避免不同项目 key 冲突。

## 12. 国际化

国际化入口：

- `src/locales/index.ts`
- `src/locales/lang/zh-CN.ts`
- `src/locales/lang/en-US.ts`
- `src/locales/lang/<locale>/ballcat.json`

`main.ts` 中如果 `enableI18n = true`，会先安装 i18n，再注册 router 和 mount：

```ts
installI18n(app).then(() => {
  app.use(router)
  app.mount('#app')
})
```

这样可以避免 401 弹窗等早期请求发生时国际化资源尚未加载。

请求层会自动注入：

```http
Accept-Language: zh-CN
```

新增文案时优先放入 locale 文件，业务组件内避免硬编码大量可见文案。

### 15.2 Nginx 配置要点

Vue Router 使用 history 模式，生产部署必须配置 fallback：

```nginx
location / {
  root /usr/share/nginx/html;
  index index.html;
  try_files $uri $uri/ /index.html;
}
```

`VITE_API_URL=/api` 时，需要反向代理：

```nginx
location /api/ {
  proxy_pass http://backend-server/;
  proxy_set_header Host $host;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_set_header X-Forwarded-Proto $scheme;
}
```

如果后端接口本身带上下文路径，需要按实际后端路径调整 `proxy_pass` 和前端 `VITE_API_URL`，保持浏览器请求路径与 Nginx 代理规则一致。

### 15.3 部署检查项

- 直接刷新业务页面不应 404。
- `/api` 请求应被代理到后端。
- 登录后动态菜单正常加载。
- 静态资源路径正常。
- 生产环境接口超时时间为 `.env.production` 的 `10000`。

代码风格：

- 使用 TypeScript 类型，不用 `any` 绕过类型，除非现有组件类型确有缺口。

## 17. 常见问题

### 17.1 页面刷新后 404

生产 Nginx 未配置 history fallback。添加：

```nginx
try_files $uri $uri/ /index.html;
```

### 17.2 新菜单打开异常页

检查后端菜单 `uri` 是否能匹配到 `src/views` 下的文件。支持：

```text
xxx/yyy/Page
xxx/yyy/Page.vue
xxx/yyy/index
xxx/yyy/index.vue
```

### 17.3 字典显示为空

检查：

- `dict-code` 是否正确。
- 后端字典项是否启用。
- 字典值类型是否和业务字段类型一致。
- LocalStorage 中旧缓存是否未失效，可清理 `breadj-admin/dict:<dictCode>` 后重试。

### 17.4 操作按钮不显示

检查：

- 用户信息中是否包含对应权限码。
- 前端 `hasPermission` 的权限码是否与后端一致。
- 菜单和按钮权限是否已经重新登录后刷新。

### 17.5 接口 401 后重复弹窗

项目已在 axios 401 处理中调用 `Modal.destroyAll()` 并清理用户状态。若新增请求库或绕过 `httpClient`，需要同步处理 401，否则可能出现重复提示。
