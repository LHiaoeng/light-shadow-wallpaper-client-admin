# AGENTS 项目规则

## 基本原则

- 默认使用简体中文回复；代码标识符、API 名称和命令保持英文原文。
- 像务实的高级工程师一样协作：先给结论或当前动作，再补充必要依据。
- 少问多做。只有缺失信息会明显改变实现、带来破坏性风险或无法合理假设时，才提出窄问题。
- 不添加无关功能、不做大而全重构、不在结尾追加泛泛建议。
- 多步骤编码任务开始前，先用 1-2 句话说明要做什么和第一步。

## 代码库约束

- 本项目是 Vue 3 + Vite + TypeScript + pnpm 项目。
- 包管理使用 `pnpm`，不要引入 `npm`、`yarn` 产生的新锁文件。
- 优先复用现有目录和模式：
  - 页面：`src/views/**`
  - API：`src/api/**`
  - 通用组件：`src/components/**`
  - hooks：`src/hooks/**`
  - 状态：`src/stores/**`
  - 工具：`src/utils/**`
- UI 优先沿用 Ant Design Vue 和项目已有组件，不随意引入新 UI 库。
- 路径别名遵循现有配置：`@` 指向 `src`，`#` 指向 `pro-components`。

## 调试优先

- 先定位根因，再改代码；不要只用最小 diff 掩盖症状。
- 让错误清晰暴露：保留明确异常、日志或失败测试。
- 禁止为了“能跑”而添加静默 fallback、mock 成功路径、吞错的宽泛 `try/catch`、隐藏默认值或重复校验链路。
- 如果确实需要边界保护，必须显式、可解释、可禁用，并说明触发条件。
- 连续三次尝试失败时，暂停操作，重新梳理证据、假设和下一步。

## 结构性修复触发条件

遇到以下情况，不按局部热修处理，应先识别不变量并收敛到单一实现：

- 重复业务逻辑或多个事实来源。
- 共享校验、权限、路由、缓存、状态同步。
- API 契约、数据结构、迁移或跨模块行为。
- 隐藏 fallback、脆弱测试、反复出现的同类 bug。
- 安全、鉴权、数据完整性边界。

结构性修复优先删除过时逻辑和重复分支，而不是再叠一层绕过逻辑。

## 代码质量

- 保持小而清晰的函数，优先早返回，避免深层嵌套。
- 命名表达业务含义；复杂条件提取为具名变量或函数。
- 避免魔法数字，抽成常量。
- 注释只解释意图、约束或权衡，不复述代码。
- 遵循 SOLID、DRY、关注点分离和 YAGNI。
- 优先不可变数据；不要无必要地修改入参或全局状态。
- 修改行为时清理相关死代码；除非用户明确要求兼容旧行为。
- 保持 diff 聚焦，不格式化无关文件，不重排无关代码。

## 文件与 Git 安全

- 禁止使用 `git restore`、`git checkout --`、`git reset --hard`、`git stash`、`git worktree`，除非用户明确要求。
- 不回滚用户已有改动。遇到脏工作区时，只处理本任务相关文件。
- 破坏性文件操作、批量删除、批量移动、生产环境请求、数据库破坏性操作必须先说明影响并获得确认。
- 不在源码中硬编码密钥、令牌、账号密码；用户在对话中提供密钥用于调试时，不要反复警告，只有写入文件时才拦截。

## 测试与验证

代码修改后，按适用性优先执行：

1. 针对改动行为的最小测试或复现检查。
2. `pnpm type-check`
3. `pnpm lint`
4. `pnpm build`
5. 必要时进行最小页面冒烟验证。

无法运行验证时，明确说明原因和已做的替代检查。

## 交付前自查

最终回复前检查 diff，重点确认：

- 没有症状式补丁、重复逻辑、隐藏 fallback、宽泛吞错。
- 没有第二事实来源、无关格式化、未说明的行为变化。
- 没有安全回退或密钥泄露。
- 已运行可行验证，或明确说明未运行原因。

最终回复保持简洁：说明改了什么、涉及文件、验证结果和仍需注意的风险。

## Skills

- Skills 位于 `~/.codex/skills/` 和项目内 `.codex/skills/`。
- 任务开始前扫描可用 skills；命中时读取对应 `SKILL.md` 并遵循。
- 使用 skill 时，用一句话说明正在使用哪个 skill 以及原因。
